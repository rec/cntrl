# MIDI monitor

The `midi-monitor` page shows MIDI received by the pedal and MIDI successfully
written to its local output drivers. Add it to the setup's named pages:

```toml
[pages.monitor]
type = 'midi-monitor'
min_windows = 1
```

The region allocator chooses the layout from the number of windows received:

| Windows | Layout, left to right |
| --- | --- |
| 1 | Combined incoming and outgoing traffic |
| 2 | Incoming, Outgoing |
| 3 | Incoming, Combined, Outgoing |

The minimum defaults to one and may be zero. The monitor can use up to three
windows. Raise `min_windows` to reserve more, provided every selectable region
combination still fits. Its region can appear on either side; setup allocation
priority determines spare windows. See [Pages](pages.md). Background patches
continue when all displays belong to the monitor.

Select the page through the usual Pages and tools menu or page-cycle control.
The monitor observes all enabled endpoints and USB cables exposed by the
target. Opening it does not enable disabled transports or change routing.

## Reading the windows

Each event uses three compact rows:

1. Seconds and milliseconds since opening the monitor, direction (`I` for
   Incoming, `O` for Outgoing), endpoint alias and cable number. Cable numbers
   follow the transport's zero-based numbering; physical endpoints use 0.
   A `~` or an ellipsis marks a shortened endpoint label. `test` identifies
   cable-test traffic when the diagnostic service is active.
2. A decoded summary, including channels 1–16 and programs 1–128. Literal
   Note Off and zero-velocity Note On remain distinct.
3. The observed hexadecimal MIDI bytes. `(running)` means the status byte was
   supplied by MIDI running status and is therefore omitted from the byte row.

Incoming includes messages received before filtering, routing and forwarding
decisions. A message discarded by a processing rule still appears in Incoming.
Outgoing shows actual processed or generated bytes, including patch messages,
counters, expression, clock, file playback, forwarding, panic and cleanup.
Fan-out appears once per successful destination write. Internal route handoffs
do not create duplicate observations.

An output waiting in a queue or rejected by a driver is not shown as sent.
Outgoing means local driver acceptance, not confirmation that an instrument
received or applied the message.

Clock, Active Sensing and other real-time traffic remain visible. SysEx appears
as ordered chunks of up to three bytes, marked `start`, `cont` and `/end` with
the chunk length. Every chunk retains all its bytes, so no payload preview is
silently truncated. USB headers and padding are not MIDI bytes. Unexpected or
interrupted input is shown as `raw / incomplete`; a partial message idle for
250 milliseconds is also marked incomplete. Decoders are separate for each
endpoint, cable and direction.

## Freeze and history

- Confirm freezes the display. Confirm again returns to live traffic.
- Previous and Next move the shared observation cursor backward and forward
  while frozen. Both directional windows and Combined use the same cursor.
- Back opens the normal menu. The page-cycle control continues to select other
  pages. If those roles share a button, page cycling keeps its usual priority.

The history holds 128 entries, shared by every window. Dense clock or SysEx
traffic can fill it quickly. `Hist-N` counts entries overwritten in monitor
history, independently of actual MIDI delivery or routing drop counters.
Capture continues while frozen; if the frozen position is overwritten, the
cursor moves to the oldest retained entry and `advanced` appears in the status.

Capture starts with empty history when a monitor page is first selected.
Capture continues under menus, without focus and with zero allocated windows.
Selecting away from the last monitor view or loading a setup releases capture
storage. Returning starts a fresh history. Multiple selected monitor views
share history and the observation cursor. When an adapter reports a disconnected or replaced endpoint, it is
marked and its partial messages and running status are reset before observing
the new connection. Passive DIN and TRS cables cannot report unplugging.

## Limits

Capture and decoder storage together are capped below 16 KiB and allocated
through the existing heap budget only while the monitor is open. If memory is
unavailable, the page reports it and MIDI continues normally. Leave and reopen
the page to try again after freeing resources.

The screen refreshes at most ten times per second for incoming traffic, with
immediate updates for controls. Capturing and maintaining history perform
bounded work and do not wait for the display. This is a live diagnostic view,
not a lossless recording or an SD logger. Use MIDI file recording when a
performance needs to be saved.
